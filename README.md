# RBS Circuit Lab

A 3D electronics lab for kids, in one HTML page (Three.js 0.165, everything modelled in code).
Build circuits on a breadboard, wire them up, write code and press **Start simulation**.

- **Boards:** RBS Learning Board (Arduino-style, C++), RBS Pi 4 and RBS Pi 5 (Python with RPi.GPIO), RBS ESP32 DevKit (Arduino C++ or MicroPython), RBS bit (drag-and-drop blocks; 5 × 5 LEDs, buttons A and B, rings 0, 1, 2, 3V and GND)
- **Blocks:** click the RBS bit and the code panel opens its Blocks tab (Blockly 10.4.3 from cdnjs, loaded the first time): Events, Display, Input, Sound, Game (sprites, score, life, countdown, game over), Loops, Logic, Variables, Math, Text, Lists, Functions, Pins and Serial, plus an Examples menu (Hello, Dice, Dodge game, Light meter, Thermometer, Music box). The blocks are saved with the circuit. Its first group, *Computing with RBS bit (curriculum 1–26)*, has one program for each project of the Roboticschools "Computing with Microbit" module, from 1 · LEDs to 26 · Dot dodger. There are two exceptions: 20 (Bluetooth from a phone) and 27–30 (Scratch) need things outside the lab. Touch pins: *when pin P0/P1/P2 is pressed* and *pin is pressed*. While a program runs, hold a ring, or a **Banana (touch key)** (Inputs) clipped to it. *RBS bit + banana piano on clips* in the Examples menu builds project 11. A button pressed again while its handler is still running waits its turn (up to 10), as on the real board
- **RBS bit power and colours:** while it is selected, the top bar shows its design colours (the printed sawtooth and A/B flags: cyan, orange, green, pink, purple, yellow, red, white; the board stays black). Start asks for the power: a micro-USB cable from the laptop (3.3 V) or a 2 × 18650 Li-ion battery holder with an on/off switch, plugged into its battery socket through a 3.3 V regulator lead (click the holder's switch, or use the toolbar's Battery ON/OFF, to cut the power); docked in the expansion board, that board powers it instead. While a program runs, the toolbar shows the sensors it uses (tilt, shake, temperature, light, compass, sound, A+B)
- **Crocodile clips:** a wire from one of the RBS bit's rings (0, 1, 2, 3V, GND) is a crocodile-clip lead. Its nickel jaws bite the ring and a PVC boot comes in the wire's colour; the floppy cable lies on the table or on the parts under it. The far end plugs into a pin or breadboard hole as usual. Sensors and other parts run from the 3V ring (3.3 V on USB and on the battery holder's regulated lead; parts count as powered from 2.7 V)
- **Extensions** (blocks, like the MakeCode website's): **+ Extensions** at the bottom of the block categories opens a gallery. *NeoPixel* (strip at a pin, show colour, rainbow, bar graph, set pixel, show, clear, brightness, shift/rotate, colours, RGB, HSL), *Servo* (angle, continuous speed, stop, pulse width), *Sonar* (HC-SR04 ping in cm, inches or µs), *DHT11* (temperature °C/°F, humidity, answered?) and *Sensor kit* (PIR motion, IR obstacle, LDR dark, rain, MQ-2 smoke; soil moisture, rain wetness, gas, pot and joystick as 0–100), *LCD1602 I2C* (start, text and numbers at x/y, clear, backlight), *OLED SSD1306* (8 lines of text), *LED matrix MAX7219* (pictures, dots, brightness), *Keypad 4×4* (row and column pins, the key pressed) and *MPU-6050* (tilt angles, acceleration, rotation speed). The I2C ones (LCD, OLED, MPU-6050) go on the RBS bit Driver Expansion Board's I2C port (P20 SDA, P19 SCL). The blocks drive the lab's real parts wired to the rings. If nothing answers on that pin, the serial monitor says what to clip where. Added extensions are remembered, and a program that uses one turns it on again
- **Upload to a real RBS bit:** the **Upload** button beside Reset, on the Blocks tab, turns the blocks into MicroPython and checks every block. That covers all extensions and the Motor driver blocks, and the window lists anything that works differently on the real board. It then packs the program into a .hex with the MicroPython V2 firmware (`firmware/microbit-micropython-v2.hex`, MIT, from the official Python Editor) using microbit-fs. **USB cable** opens the browser's device popup straight from the click (the board shows as "… CMSIS-DAP"), builds the .hex while you pick, and flashes it over WebUSB with dapjs. Inside claude.ai, where USB is blocked, it opens the lab on its own page with your circuit and program instead (your website, or http://localhost:8800 on this computer). **Download .hex** works anywhere: drag the file onto the board's USB drive (inside claude.ai it comes as a .zip). **Python code** shows the MicroPython to copy. **Bluetooth** connects to a board running the **RBS bit Bluetooth program** and drives it: forward, backward, left, right, z, x, stop, speed0–255, on, off and the RGB colours, the same commands as the Roboticschools controller app. MicroPython has no Bluetooth, so a board running a lab program is invisible to every Bluetooth search; **Install Bluetooth program (USB)** in the Bluetooth window puts the Bluetooth program back on in one click (or **Download Bluetooth program** and drag it onto the drive). A browser can't send programs over Bluetooth: the official @microbit/microbit-connection library lists "flash via Bluetooth" as not supported on the web. USB and Bluetooth need Chrome or Edge on a page that is allowed to use them: the lab on its own page, not inside claude.ai.
- **4WD Robot Car (one robot, one table, in the lab's own view):** the **4WD Robot** button beside Examples shows the 15 projects (5 projects × 3 controllers) as a grid. Picking one builds the robot on the lab's workplane, in the same 3D view, renderer and frame loop as everything else. No other window opens. The robot (the 4-Wheel Drive Robot Car Chassis – 18650 Edition) has:
  - four TT motors with brackets, five-spoke wheels, two transparent acrylic plates and brass spacers;
  - the 2 × 18650 holder and a sensor power strip;
  - the real controller and driver parts, mounted on the top plate on brass standoffs (props.onCar);
  - the project's sensors on their mounts (the ultrasonic at the front, LDRs on the front corners, IR line sensors under the front).

  The robot's own wiring is drawn as a neat harness, not as the lab's usual jumper arcs:
  - every wire leaves its pin over the nearest edge of its part and runs in a channel just above the top plate, under the raised boards;
  - wires between the same two parts lie side by side as a ribbon;
  - the motor and battery leads end in JST-XH plugs in the driver's connectors (the Rev3's paired motors share one plug through a Y-lead);
  - a cable to a part on the bench (the joystick) lies flat on the table and climbs the robot's side.

  The circuit, the wiring table and the current-flow dots use the same wires. A **Connectors** check on the Project tab confirms that every motor and the battery is on a JST connector of the right kind.

  The car, everything mounted on it and the wires between them move as one assembly when it drives. **Reset robot** puts it back where it stands on the workplane. The line track, lamps and obstacles are laid on the same workplane.

  Pick a controller (Arduino Uno, RBS bit, ESP32) and a project (Basic 4WD Movement, Light Following, Ultrasonic Obstacle Avoiding, IR Line Following, Joystick Controlled). The 15 combinations:
  - Arduino + Arduino Motor Shield Rev3 (two channels, left and right motors paired) or + L293D shield (four channels, AFMotor);
  - RBS bit + RBS bit Driver Expansion Board (pxt-motor blocks, with a MakeCode TypeScript version);
  - ESP32 + HG7881 (LEDC PWM).

  The programs run in the lab's own interpreters. The motor voltages they produce drive the robot through a fixed-step skid-steer physics model. The sensors read the workplane:
  - the ultrasonic casts rays at obstacles, other parts and the fence;
  - the LDRs see the lamp's position and angle;
  - the IR line sensors read the drawn line.

  Motor, battery and physics values that are not from a datasheet are marked "illustrative" and can be edited.

  **Joystick Controlled Robot** uses the lab's dual-axis joystick module, which stays on the bench wired to the robot like a tethered remote:
  - Arduino: VRx/VRy/SW on A2/A3/D2. RBS bit: P1/P2/P0. ESP32: GPIO 34/35/27.
  - The program calibrates the centre and applies a dead zone. It mixes forward and turn into the left and right motors, and a press of the stick (SW, with a pull-up) toggles slow mode.
  - In this project the panel's joystick, arrows and W/A/S/D move the module's lever, so the program reads it as on real hardware.
  - The module's wires follow the robot as it drives.

  The **robot panel** sits in the corner of the 3D view and can be collapsed or hidden. Its header shows the project, controller and driver and who drives the motors, and a status bar shows speed, battery and program state.
  - **Drive:**
    - a joystick (mouse or touch, with a direction pointer, a dead zone, speed limits, acceleration and turning settings), arrow buttons, Stop and a speed slider;
    - a top-view dashboard of the four wheels (green forward, orange backward, with rpm), plus position, heading, speed and distance;
    - W/A/S/D on the keyboard, with Space as an emergency stop;
    - control modes: manual, program, light, obstacle or line following, a virtual Bluetooth remote that sends F/B/L/R/S to the program's Serial input, and voice (where the browser allows it);
    - an ultrasonic safety stop.
    - Manual driving goes through the same driver and motor models as the programs.
  - **Project:** controller and driver buttons, five project cards, a "How it works · what you learn" section (objectives, what you should see, common mistakes, challenges), the program's constants as settings, hardware checks, wiring, and a hardware compatibility table.
  - **Table:** the track, lamps and obstacles (add, drag, resize), and Reset table.
  - **View:** eight camera views, follow, overlays (wheels, motor direction, wiring, beams, values, path, collision outline) and the parts list.

  The source is in `robot4wd/` (core, projects, sensors, Motor Shield Rev3, the in-view panel); `python3 -I robot4wd/splice.py` puts it into index.html. Plans and test results are in `robot4wd/CHECKLIST.md`.
- **RBS bit example circuits** (Examples menu). Basic parts go straight on the RBS bit with crocodile leads: *RBS bit + LED on clips* and *+ RGB LED on clips* (rings 0, 1, 2 and GND). Everything else is built on the RBS bit Driver Expansion Board: the RBS bit stands in its slot, a 2 × 18650 battery holder on VIN powers it, and each part's cable goes to a G V S header. Those examples are *+ NeoPixel rainbow* (P0), *+ servo* (port S1, with the Motor driver servo block), *+ weather station* (DHT11 on P0), *+ plant monitor* (soil on P1), *+ motion alarm* (PIR on P1) and *+ distance meter* (sonar on a breadboard, TRIG P1, ECHO P2). Each one builds the circuit and loads its blocks; at Start choose *Expansion board* as the power. The same programs are in the Examples list above the blocks
- **Parts:** LEDs, RGB LED, buzzer, servo, pump, pot, joystick, keypad, LCD, OLED, LED matrix, LED strip, shields and sensors (LDR, IR, PIR, ultrasonic, soil, DHT11, MQ-2, rain, MPU-6050)
- **RBS bit Driver Expansion Board** (Shields): micro:bit slot, DC motor outputs M1 (1A±) M2 (1B±) M3 (2A±) M4 (2B±), steppers M1_M2 and M3_M4, 9 GPIO (P0 P1 P2 P8 P12–P16) and 8 servo (S1–S8) G-V-S headers, I2C port, VIN terminal, VOUT, power switch and light. Drag the RBS bit onto the slot (or the board onto the RBS bit) and it stands in the edge connector: its pins reach the headers, and Start offers *Expansion board* as its power. **Motor driver** blocks, after DFRobot's pxt-motor extension: servo S1–S8, motor M1–M4 CW/CCW speed 0–255, motor stop, stop all, stepper 42/28 by degrees or turns, dual stepper. **Demo circuit** (its toolbar) docks an RBS bit and wires a battery pack, two TT motors, a stepper, a servo, a pot, an IR sensor, a traffic light and a buzzer, plus a blocks program. Click a part to see what it is, click the switch to flip it, **Inspect** opens a close-up with Front / Back / Left / Right / Top / Bottom / Isometric / Perspective views, an orthographic toggle and every part and pin clickable. *Test motors* drives M1–M4 by hand; a simulation engine can use `window.RBSLab.rbsbitDriver` (parts, pins with endpoints and 3D positions, `setSwitch`, `setMotor('M1', duty)`, `setServo`, `setPin`, `readPin`, `docked`, `onChange`)
- **To drive and power it:** *Battery Holder 2 × 18650* (Power: two Li-ion cells in parallel, 3.7 V, with an on/off switch you can click; it replaces the 3 × AA pack, which still loads in saved circuits). It connects itself to the RBS bit Driver Expansion Board: added from the Components panel, or clicked while its leads are free, it wires red to VIN + and black to VIN − of the nearest board whose VIN is free (a card click also sets it down beside that terminal), and a board added later takes a holder lying free, *DC Gear Motor (TT)* with its wheel and *Stepper Motor 42* (NEMA 17, 4 wires) in Motion
- **HG7881 H-Bridge 4CH DC – 2CH Stepper Motor Driver Board** (Shields): four HG7881 (L9110S-type) H-bridges, one per motor A–D, each with two 10 kΩ input pull-ups. Header A1 A2 B1 B2 C1 C2 D1 D2 + −, an 8-way screw terminal (Motor D C B A, OB/OA in each pair) with a JST-XH adapter in each pair, a JST-XH power header, and a power LED. One supply on + powers the chips and the motors (2.5–12 V, 800 mA a channel). Each motor takes two signal pins: X1 HIGH + X2 LOW = forward, X1 LOW + X2 HIGH = backward, both LOW or both HIGH = brake, and PWM on one pin sets the speed. Two steppers work on A+B and C+D. Its toolbar has *Connect ESP32* (A1–D2 to GPIO 25 26 32 33 18 19 22 23, GND to −), *Connect battery* and *Inspect*, a close-up with 8 CAD views, ortho/persp, every part and pin clickable, and a compatibility check (supply, common ground, ESP32 pins, motor current). Swapping + and − burns the chips out. Simulation API: `window.RBSLab.hg7881` (parts and pins with unique ids, endpoints and 3D positions, channels, steppers, checks, `setInput`, `connectEsp32`, `connectBattery`). Board size is 48 × 37 mm (retailer data); the header and terminal order follow the reference sheet, so check them against the physical board
- **RBS ESP32 DevKit runs code:** Arduino C++ (pinMode, digitalWrite/Read, analogWrite, ledcAttach/ledcWrite plus the core 2.x ledcSetup/ledcAttachPin, analogRead 12-bit, dacWrite, and every library the Learning Board has: Servo/ESP32Servo, DHT, NeoPixel, LCD and MPU-6050 on I2C GPIO 21/22, keypad, tone, pulseIn) or MicroPython (`machine.Pin/PWM/ADC/DAC/time_pulse_us`, `dht`, `time.sleep_ms`…). The code runs on the ESP32 when it is the only board for that language, or when C++ mentions ESP32 / Python imports `machine`. It follows the real board's rules: GPIO 34–39 are inputs only, GPIO 6–11 are refused, digitalWrite is ignored on a PWM pin (core 3.x), and MicroPython's PWM starts at 50 % and its ADC at 0 dB unless set. *Check parts* on its toolbar lists every wired part against its 3.3 V pins (5 V signals, ADC2 with Wi-Fi, boot pins, I2C pins, motors on pins), plus a table for every part in the lab. 15 examples: DC motor, 4-motor car and stepper with the HG7881, pot speed knob, ultrasonic stop, DHT11 + LCD, PIR alarm, soil + pump, servo and LDR, several in both C++ and MicroPython
- **Upload MicroPython to a real ESP32 over USB:** in Python mode the **Upload** button opens the ESP32 window. It first checks the code: Python, modules built into ESP32 MicroPython, pins (flash 6–11, inputs-only 34–39, boot pins, ADC2 with Wi-Fi, USB-serial 1/3), PWM without duty=, and C++ by mistake. It also checks the lab circuit and the browser. **USB cable** picks the board's port with Web Serial (CP210x, CH340/CH9102, FTDI or Espressif native USB) and stops what runs. It then enters MicroPython's raw REPL (as mpremote and Thonny do) and asks the board what it is: ESP32, MicroPython version, free RAM and flash, and every imported module. Next it writes `main.py` in 256-byte chunks, verifies its size, soft-reboots and streams the output, with Stop, Restart and Disconnect. **Run once** runs the code without saving it. Where the page cannot reach USB (inside claude.ai), **Stand-alone uploader** saves `esp32-usb-upload.html`: the same engine and checks with the code inside, for Chrome or Edge. **main.py file** saves or copies the code for Thonny or mpremote. Inside claude.ai (no Web Serial there, and macOS's own CP210x/CH340 drivers keep WebUSB off the ESP32's USB chip), **USB cable** opens the lab on this computer at http://localhost:8800 (`python3 -m http.server 8800 --bind 127.0.0.1` in `dist/site`, the same place the RBS bit upload works). The circuit and code travel in the address (`?v=<stamp>#rbs-upload=…&via=esp`; the `?v=` stops the browser from using an old cached copy), and the ESP32 window opens there by itself with USB ready. The website is offered as a link. `dist/site/index.html` is the deploy-pages.sh wrapper around index.html: rebuild it after changing the lab. The ESP32 needs MicroPython flashed once (Thonny → Install MicroPython). Tested against a simulated MicroPython ESP32; check it on a real board
- **Upload Arduino C++ to a real ESP32:** in C++ mode the same **Upload** button converts the sketch to MicroPython (`espCppToPy`, built on the lab's C++ parser), checks it, and uploads it as `main.py`. Each Arduino function the sketch uses gets a small MicroPython version at the top of the file: pinMode, digitalWrite/Read, analogWrite, analogRead (11 dB, 0–3.3 V), ledcAttach/ledcWrite (core 3) and ledcSetup/ledcAttachPin (core 2), dacWrite, tone/noTone (tone durations end during delay), pulseIn, delay, millis/micros, map, constrain, random, Serial.print/println/printf, Serial.available/read/peek (USB input through `sys.stdin` and `select.poll`), Servo (ESP32Servo's 544–2400 µs), DHT11/22 (NaN when there is no answer) and Adafruit_NeoPixel. It keeps C's whole-number division, `static` locals, switch/case, for loops and int truncation. Libraries with no MicroPython version (LCD, keypad, LED matrix, MPU-6050, L293D's AFMotor) are marked ✗ with their lines; for those, use the Arduino IDE (board ESP32 Dev Module). **MicroPython code** shows the result, and **Open in the Python editor** puts it in the Python tab. While the board runs, the window's **Send** box (also in the stand-alone uploader) types into its Serial input: for example, F, B, L, R, S for the 4WD robot's ESP32 projects, which all convert without changes. In the lab, the ESP32's MicroPython reads the same input queue (`run.rx`) that the robot's drive buttons fill. 9 of the 10 ESP32 C++ examples behave the same in the lab as C++ and as converted MicroPython. The exception is the LCD weather station, which is stopped at the ✗ because its LCD has no MicroPython version.
- **JST-XH connectors (2.5 mm), as on the kit:** the shields keep their screw terminals. A white JST-XH male adapter is clamped in each motor pair and in the power terminal; its pins are bent out to the screws' 5 mm pitch: the RBS bit Driver Expansion Board (green terminals: M1–M4, VIN), the HG7881 (blue terminal: Motor A–D) and the L293D Motor Shield (blue terminals: M1–M4, EXT_PWR). The HG7881 has no power terminal, so its power comes in on a JST-XH header on the board. The DC Gear Motor (TT), the Mini Water Pump, the Stepper Motor 42 (two plugs, coil A and coil B) and the Battery Holder 2 × 18650 have female JST plugs on red/black leads; a plug lies on the table until its part is plugged in. **Click a motor or battery, or add one, and it plugs into the nearest shield with a free connector of its kind**; a stepper takes a pair (A + B / C + D, M1 + M2 / M3 + M4). Adding a shield plugs in any loose motors. A plugged lead is drawn from the part across the table into a female plug lying in its adapter, with the wires out of its back. A battery on the L293D's EXT_PWR sets its motor voltage (less 1.4 V)
- **Hands-on:** turn sensor trim pots with a screwdriver, turn the pot knob and push the joystick with the mouse
- **Controls:** drag to orbit, Shift + move to turn, Ctrl + move to pan, scroll to zoom, Space to find your circuit

## Files

| Path | What it is |
|---|---|
| `index.html` | The whole lab (published as a claude.ai artifact) |
| `rbs-bit/rbs-bit.js` | The RBS bit board as a reusable Three.js module (see `rbs-bit/README.md`); `index.html` carries a copy |
| `rbs-bit/viewer.html` | Standalone RBS bit viewer: orthographic and perspective views, part info, LEDs, buttons, wires |
| `rbs-bit/embed.pl` | Copies `rbs-bit/rbs-bit.js` into `index.html` |
| `firmware/microbit-micropython-v2.hex` | MicroPython for the RBS bit V2 (MIT; MicroPython v1.18, copied from the official Python Editor's repository, microbit-foundation/python-editor-v3): the Upload button packs the blocks into it |
| `firmware/rbs-bit-bluetooth/` | The RBS bit Bluetooth program: `main.ts` and `pxt.json` (MakeCode, Bluetooth extension, "No Pairing Required"), and `rbs-bit-bluetooth.hex`, the V2 part of what MakeCode 9.0.12 compiles from them. It advertises the Bluetooth UART service and runs the controller commands: wheels on the RBS bit Driver Expansion Board (left M1 + M3, right M2 + M4, right side mirrored), RGB LED on P0/P1/P2, button A stops, button B scrolls the board's five-letter Bluetooth name. The lab carries the same .hex gzipped in `RBU_BT_HEX_GZ` for its Install button; after changing `main.ts`, compile it again in MakeCode (import the two files, Download), keep the V2 part, and replace both. |
| `robot4wd/` | The 4WD Robot Car simulator: `car4wd-core.js` (profiles, model, motor and battery models, physics, table, sensor mounts, the car part), `projects.js` (the 12 project setups and their code generators), `sensors.js` (the analog LDR and TCRT5000 line sensor parts), `amsr3.js` (Arduino Motor Shield Rev3), `car4wd-hud.js` (the table objects, overlays and robot panel in the lab's own view, manual driving, checks, the API), `splice.py` (puts them into index.html) and `CHECKLIST.md` (the plan and the test log). |
| `build.sh` | Refreshes that copy, then wraps the pages into `dist/test.html` and `dist/rbs-bit/viewer.html` for local testing |
| `tests/*.cjs` | Playwright checks and renders (examples, screwdriver, controls, part close-ups; `t-rbsbitdrv.cjs` for the driver board) |

## Publish the website

`./deploy-pages.sh` builds the lab as a full page, with the MicroPython firmware next to it, and pushes it to the `gh-pages` branch. Once, in GitHub, open Settings → Pages and choose "Deploy from a branch": `gh-pages`, `/ (root)`. The site is https://roboticschools-website.github.io/rbs-circuits/. On its own page the lab uploads to the RBS bit over USB and shows the Bluetooth device popup. Inside claude.ai it opens itself in a new tab for those.

## Run locally

```sh
./build.sh
python3 -m http.server 8765
# open http://localhost:8765/dist/test.html (the lab) or http://localhost:8765/dist/rbs-bit/viewer.html (the RBS bit viewer)
```

The tests expect the page at `http://localhost:8765/test.html`; copy `dist/test.html` to the folder root (or adjust the URL) before running them with Node and Playwright.
